SYSTEM ARCHITECTURE OVERVIEW
================================================================================

CryoNav AI follows a modern React-based single-page application (SPA) 
architecture with a component-driven design pattern. The application is built 
with modularity, reusability, and maintainability in mind.

ARCHITECTURAL LAYERS:
================================================================================

1. PRESENTATION LAYER (UI Components)
   ├── App.jsx (Root component)
   ├── Panels/ (Dashboard panels)
   ├── Map/ (Leaflet map components)
   ├── Modals/ (Dialog boxes)
   └── Common/ (Reusable UI elements)

2. STATE MANAGEMENT LAYER
   ├── React Hooks (useState, useEffect, useCallback)
   ├── Custom Hooks (useScenario, usePolling)
   └── Component-level state

3. BUSINESS LOGIC LAYER
   ├── utils/ (Calculation functions)
   ├── services/ (Data providers)
   └── hooks/ (Custom logic hooks)

4. DATA ACCESS LAYER
   ├── API Service (Axios-based HTTP client)
   ├── Mock Data Service (Fallback data)
   └── Configuration (API endpoints, constants)

5. EXTERNAL SERVICES
   ├── Backend API (Python/Flask expected)
   └── Third-party Libraries (Leaflet, Axios)

================================================================================
DESIGN PATTERNS USED
================================================================================

1. COMPONENT-BASED ARCHITECTURE
   - Each UI element is an isolated, reusable React component
   - Components follow single responsibility principle
   - Clear separation between presentational and container components

2. CUSTOM HOOKS PATTERN
   - Business logic extracted into custom hooks
   - useScenario: Manages scenario progression
   - usePolling: Handles periodic data fetching
   - Promotes code reuse and separation of concerns

3. SERVICE LAYER PATTERN
   - API interactions abstracted into service modules
   - api.js: HTTP request handling
   - mockData.js: Fallback data generation
   - scenarioData.js: Static scenario definitions

4. CONFIGURATION MANAGEMENT
   - Centralized config.js file
   - Environment-based settings
   - Easy toggle between mock and live data

5. PROP DRILLING MITIGATION
   - Callback functions passed down component tree
   - Event handlers lifted to parent components
   - Minimal prop drilling through shallow component trees

6. GRACEFUL DEGRADATION
   - Automatic fallback to mock data when API fails
   - Error boundary handling
   - Null-safe rendering patterns

DATA FLOW ARCHITECTURE
================================================================================

UNIDIRECTIONAL DATA FLOW:

1. USER ACTION / TIMER EVENT
   ↓
2. EVENT HANDLER (onClick, useEffect)
   ↓
3. API CALL (via services/api.js)
   ↓
4. BACKEND RESPONSE / MOCK DATA
   ↓
5. STATE UPDATE (setState hooks)
   ↓
6. COMPONENT RE-RENDER
   ↓
7. UI UPDATE (DOM changes)

EXAMPLE FLOW - Scenario Progression:
User clicks "Next Scenario" button
  → nextScenario() called in useScenario hook
  → advanceTime() API call
  → Backend increments scenario counter
  → New scenario data returned
  → setScenario() updates state
  → App re-renders with new scenario
  → All child components receive updated data
  → Map markers, routes, panels update automatically

================================================================================
STATE MANAGEMENT STRATEGY
================================================================================

LOCAL COMPONENT STATE:
- Used for UI-specific state (modal open/closed, selected route, etc.)
- Managed with useState hook
- Does not affect other components

LIFTED STATE:
- Scenario number (managed in App.jsx)
- Navigation data (fetched and passed down)
- Risk assessment (shared across panels)

DERIVED STATE:
- Calculated values (risk level from percentage)
- Filtered data (visible icebergs, active routes)
- Formatted displays (time conversions, distance units)

NO GLOBAL STATE MANAGEMENT:
- No Redux, Context API, or external state libraries
- Component tree is shallow enough for prop drilling
- Future scaling may benefit from Context API

================================================================================
API INTEGRATION ARCHITECTURE
================================================================================

API SERVICE ABSTRACTION:

api.js exports functions for each endpoint:
- getHealth()          → Check backend status
- getIceAnalysis()     → Fetch ice concentration data
- getIcebergs()        → Get detected icebergs
- getPredictions()     → Get drift trajectory predictions
- getRoutes()          → Fetch route options
- getRiskAssessment()  → Get current risk metrics
- getExplanation()     → Get AI-generated explanation
- advanceTime()        → Progress to next scenario
- resetDemo()          → Reset to scenario 0
- getWindData()        → Fetch wind vector field

FALLBACK MECHANISM:

Each API function:
1. Checks useMockData flag
2. If true, returns mock data immediately
3. If false, attempts HTTP request
4. On success, returns backend data
5. On failure, falls back to mock data
6. Logs error for debugging

MOCK DATA SYSTEM:

mockData.js provides realistic fallback data:
- Static mock structures
- Randomized values where appropriate
- Matches backend response schema exactly
- Enables standalone operation without backend

================================================================================
ERROR HANDLING STRATEGY
================================================================================

1. API LEVEL
   - Try-catch blocks in all API functions
   - Automatic fallback to mock data
   - Console logging for debugging

2. COMPONENT LEVEL
   - Null-safe rendering (optional chaining)
   - Default values for missing data
   - Loading states during transitions

3. USER FEEDBACK
   - Loading spinners during data fetch
   - Notification toasts for errors
   - Modal dialogs for critical issues

4. GRACEFUL DEGRADATION
   - App continues to function with mock data
   - Partial data rendering (show what's available)
   - No white screen of death

================================================================================
PERFORMANCE OPTIMIZATIONS
================================================================================

1. COMPONENT MEMOIZATION
   - useCallback for function references
   - Prevents unnecessary re-renders
   - Stable function identities

2. EFFICIENT RENDERING
   - Conditional rendering (&&, ternary)
   - Key props for list items
   - Minimal component depth

3. LAZY LOADING
   - Map components render only when visible
   - Modal components conditionally mounted
   - Assets loaded on demand

4. DATA CACHING
   - Mock data computed once
   - API responses not over-fetched
   - Polling intervals configured optimally

5. DEBOUNCING
   - Transition delays prevent rapid state changes
   - Smooth animations without jank
